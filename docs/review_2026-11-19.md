# Code review of 2026-11-19: what is left open

Five areas were read independently (DSP building blocks, engines and `synth.c`, hosts, web UI, tests and build).
The confirmed defects with a clear fix were corrected the same day (commits "Review fixes: ..."). This file lists
what was found and **not** fixed, most useful first, so it is not lost. Nothing here crashes or corrupts memory.

## Sound engine

- **Clicks on rare switches**: `poly` unison toggled while notes sound (copies cut in one sample, orphaned voices
  until unison is turned off); chorus mode change (taps jump); supersaw voice count raised while sounding (new
  saws enter without a fade); a drum retriggered while its tail rings (`drums.c` clears the voice, no crossfade);
  the engine-switch fade is one block (0.67 ms, the steal fade is 2 to 5 ms).
- **Block-constant gains**: the ladder's resonance compensation and drive (`ladder.c`, `k35.c`) step once per
  block while the cutoff is interpolated: small steps on fast resonance or drive sweeps.
- **Stale effect memory**: the delay stops computing after 20 s at mix 0 without emptying its lines (old echoes
  come back when the mix is raised with a long feedback); the chorus does not write its buffer when bypassed.
- **`wt` without table memory** (a board with a short arena): `wt_render` returns before ending its voices, which
  then stay active for ever.
- **Divisions inside per-sample loops** (project rule): `poly.c:291`, `modal.c:333` and `:354`, `drums.c:596` and
  `:622`. Hoisting them changes the last bit of those engines' output (golden hashes to re-record).
- **Memory on the boards**: an instance is ~340 KB with 8 parts, the DTCM is 128 KB (H745) or 64 KB (F746);
  `SYNTH_PARTS` must be lowered per target, and nothing checks the size at build time yet.
- Minor: `wt_osc` does not clamp a negative frequency (unreachable today); reverb taps read one sample early and
  the freeze comment is optimistic; `nan_count` and the event queue's drop counter cannot be read from outside;
  several `static` helpers lack the module prefix; the first `synth_init` of two instances must not run on two
  threads at once (documented in `synth.h`).

## Hosts

- `synth_play` (still untested with the MiniLab): MIDI clock messages are not forwarded; a controller unplugged
  and plugged back is not reconnected; the `c` `v` `b` `n` keys send `va` parameter ids to whatever engine is
  selected; the help text lists three engines.
- CLAP plugin: the state holds one engine (the patch format), the other engines' values come back at their
  defaults; a state loaded while playing re-initializes the engine inside `process()` (a one-off spike).
- A few unchecked allocations remain in `json.c`, `demos.c` (`seq_*`) and the wasm catalog writer; `wav.c`
  overflows its header above ~536 million frames (a song is limited to one hour).
- `-ffp-contract=off` applies to `dsp/` and `midi/` only; the host layer's parameter conversions could in theory
  round differently between compilers.
- `synth_catalog`'s instrument description lists three engine families.

## Tests and tooling

- No direct unit test for `env_rl`, `halfband`, `vfilter`, `smooth`, `denormal`, `fft`, `resonator`, nor for the
  `param_from_norm` / `param_to_norm` round trip; fm6 keyboard scaling is untested. Determinism is not checked for
  lfo, chorus, comb, formant, k35, dcblock, tempo, mseg, and several engine suites compare the left channel only.
  Only the reverb runs at other sample rates than 48 kHz.
- `tests/test_env.c` and `test_filter.c`: some comments promise more than the checks do (30 s release, 1 kHz
  through the DC blocker).
- `tools/check_rules.py` misses: quoted `#include "math.h"`, `__builtin_*` libm calls, libm functions outside its
  list (`atan2f`, `fabsf`...), non-static globals, `double` literals without the word `double`, hard-coded 48000.
- The `docs` build target rewrites tracked files (a header change dirties git silently), which also makes the
  `api` ctest unable to fail after a build.
- `docs/bench.md` predates `-ffp-contract=off` and the handle API.

## Web UI

- The step grid cannot be edited from the keyboard (cells are not focusable) and its ARIA roles are incomplete.
- The playhead ignores swing; a "held" cell with nothing before it plays as a new note.
- The worklet's UTF-8 helpers do not validate malformed sequences (catalog and messages are ASCII in practice).
