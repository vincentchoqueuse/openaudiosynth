# Open Instrument Description (OID) — draft 0.3

An open, vendor-neutral, text-based way to **describe a synthesizer**, **store sounds** for it,
**control it** and **write music** for it. Readable by humans, editable by hand, and designed so an AI
agent can use an instrument it has never seen: everything it needs (ranges, units, meaning, what moves
live, which CC) is in one self-describing file.

Proprietary formats lock sounds inside one product. OID separates *what an instrument can do* (its
description, published by the instrument itself) from *the values of a sound* (patch), *how it is
played live* (controller map) and *the notes* (patterns, songs).

Status: draft. Reference implementation: this repository. Licence of the text and schemas: the
owner's choice (suggested: CC BY 4.0 for the text, MIT for the schemas).

## 1. The files

| File | Answers | Schema |
|---|---|---|
| **Description** `catalog.json` | What can this instrument do? | `schemas/catalog.schema.json` |
| **Patch** `patches/*.json` | What are the values of this sound? | `schemas/patch.schema.json` |
| **Controller map** `controllers/*.json` | Which knob moves what, on any engine? | (section 5) |
| **Song** `songs/*.json` | Which notes, when, with which sounds and mix? | `schemas/song.schema.json` |
| **Roles** `roles.json` | What does a parameter *mean*, across instruments? | — |

The description is **generated by the instrument from its own source of truth** (here: the DSP
descriptor tables), never written by hand. Everything is UTF-8 JSON.

## 2. Principles

1. **Self-describing**: a parameter carries its type, range or choices, default, unit, scale, whether
   it can move live, its default CC, its role and one line of help about its *audible effect*.
2. **Physical values**: Hz, s, dB, `st`, `cent`, `oct`, `x`, or unitless. Never 0..1 normalized
   (normalization is a controller concern, done with `range` and `scale`).
3. **Names for precision, roles for portability**: a patch may address `cutoff` (this instrument) or
   `filter.cutoff` (any instrument that has that role). Roles are unique within an engine.
4. **Live is declared**: `realtime: true` means the parameter can be moved continuously while playing
   (CC, modulation, automation) without clicks; `false` means a setting (model, mode, voice count).
   Only `realtime` parameters should be mapped to knobs.
5. **Strict and helpful**: readers refuse unknown names, roles and choices, list the valid ones in the
   error, and clamp out-of-range numbers with a warning. Unknown fields starting with `x-` are ignored.
6. **Versioned**: the description has `oid`, patches and songs have `version`.

## 3. Description

```json
{
  "oid": "0.3",
  "instrument": {"name": "synth", "description": "..."},
  "patch_version": 1,
  "midi": {"pitch_bend": "each engine's bend_range", "cc": {"1": "mod_wheel", "64": "sustain"}},
  "global": {
    "description": "master and effect bus, shared by every engine",
    "params": {
      "reverb_mix": {"type": "float", "range": [0, 1], "default": 0, "realtime": true, "cc": 91,
                     "role": "fx.reverb.mix", "help": "plate reverb level (0 = off) ..."}
    }
  },
  "engines": {
    "va": {
      "description": "subtractive virtual analog ...",
      "voices": 8,
      "params": {
        "cutoff":    {"type": "float", "range": [20, 20000], "default": 2000, "unit": "Hz", "scale": "log",
                      "realtime": true, "cc": 74, "role": "filter.cutoff", "help": "main brightness control"},
        "osc1_wave": {"type": "enum", "choices": ["sine", "saw", "pulse", "tri", "supersaw"],
                      "default": "saw", "realtime": false, "role": "osc1.waveform", "help": "..."}
      }
    },
    "drums": {"description": "...", "voices": 16, "notes": {"kick": 36, "snare": 38}, "params": {}}
  }
}
```

Parameter fields: `type` (`float`, `int`, `enum`), `range` [min, max] or `choices`, `default`,
`unit`, `scale` (`log` when the natural control is logarithmic; linear otherwise), `realtime`, `cc`
(default assignment, optional), `role`, `help`. Global parameters exist for every engine.

## 4. Patch

```json
{"version": 1, "engine": "va", "name": "va_acid_bass", "description": "what it sounds like and why",
 "params": {"cutoff": 220, "osc2_wave": "pulse", "fx.delay.mix": 0.3},
 "audition": {"notes": "C2! C2 C3~ D#2 - C2", "bpm": 124, "step": 0.25}}
```

Only parameters that differ from the defaults are written. Keys are names or roles; values are
physical numbers or choice names.

## 5. Controller map

```json
{"oid": "0.3", "controller": "Novation Launch Control XL, factory template 1",
 "map": {"13": ["filter.cutoff", "resonator.brightness", "drum.kick.decay"], "78": "fx.reverb.mix"}}
```

A CC maps to one role/name or to a list tried in order: the first one the **current engine** has wins.
One layout therefore drives every engine. The CC value 0..127 spans the parameter's `range` with its
`scale`.

## 6. Notes, patterns, songs

- **Phrase** (string): steps separated by spaces; `C3`, `Eb2`, `F#4` (C4 = MIDI 60); chords `C3+E3+G3`;
  `-` rest; `_` tie; per note: `!` accent (velocity 127), `?` ghost (50), `~` slide into the next note
  (overlap: monophonic legato voices glide); `|` ignored.
- **Pattern** (step grid): `{"kick": "X...x...", "chat": "x.o.x.o.", "repeat": 4}`; rows are named
  notes of the engine (`notes`) or note names; `x` hit, `X` accent, `o` ghost, `.` rest. A list of
  patterns plays as sections.
- **Track**: `patch`, `notes` or `pattern`, `step` (beats), `start_step`, `repeat`, `gate`, `velocity`,
  `swing`, `humanize_velocity`, `humanize_ms`, `gain_db`, `pan`, `reverb_send`, `pump` (beat-locked
  ducking), `params` (overrides, names or roles).
- **Song**: `bpm`, `length_beats`, `tail_s`, `tracks`, `reverb`, `master`.

## 7. Roles

`roles.json` is the shared vocabulary: `filter.cutoff`, `amp.attack`, `osc<n>.detune`,
`motion.detune<n>.depth`, `voice.glide`, `resonator.decay`, `exciter.hardness`,
`drum.<instrument>.decay`, `fx.reverb.mix`… (`<n>` = index, `<instrument>` = named note). An
instrument whose code cannot carry roles may publish them in an overlay file that adds `role` to its
description.

What roles enable: portable patches (section 4), knob layouts that follow the engine (section 5),
and agents that can act on intent ("make it darker" = lower `filter.cutoff` or
`resonator.brightness`, whichever exists).

## 8. Conformance

- **Instrument**: publishes a description generated from its source of truth; every parameter has a
  role unique within its engine.
- **Reader**: validates, then plays patches (level 1), songs (level 2), controller maps (level 3).
- **Writer** (human tool or AI agent): emits files that validate against the schemas and the
  description: `python3 tools/validate.py --catalog-cmd ./build-host/host/synth_catalog`.
