# Code review of 2026-11-20: what is left open

The whole project was read in three parts (DSP library; build, tests and host tools; board, plugin and web). The
strongest findings were checked in the code. The verified defects with a small fix ("lot 1") were corrected the
same day, in the commit "Review fixes: ...". This file lists what is **not** fixed yet, grouped by when it
matters, so nothing is lost. See also `review_2026-11-19.md`.

## Fixed on 2026-11-20 (lot 1)

- The sampler keeps the pitch of its 48 kHz kits at any output rate.
- A part's modulation routes lose their destination when the part changes engine (the plugin's values follow).
- The event queue keeps reserved slots for the events that end sound (note-off, sustain up, all notes/sound off).
- Board: a network preset is not rewritten until the M7 has applied it (`done_seq`), and a kit bank is not
  rewritten until the M7 plays the last kit published (`kit_ack_seq`). A kit received while the M7 is silent is
  taken at once. The M4 initializes the queue's loss counter; the benchmark no longer indexes `presets[-2]`.
- The plugin state saves floats with 9 digits and reads them back whatever the locale (exact round trip, tested
  under `fr_FR`).
- The dev server only accepts same-origin JSON requests on `POST /api/patches`.
- JSON and kit loading check their allocations; the kit cache holds 64 kits and reports when it is full.

## Before using the rig on stage (lot 2): done on 2026-11-20

- Network fail-safe: `HEARTBEAT` message, every note stops after 500 ms without a datagram, on cable down and on
  a queue overflow (`docs/link.md`). Gap detection by numbered datagrams is left to protocol v2.
- Watchdog IWDG1 (250 ms) fed only while the audio interrupt renders; the HardFault handler zeros the DMA buffer.
- The demo arpeggio is off at power-up, toggled by a tap on the screen's title.
- NaN protection in every build: a non-finite part is reset with its current values, the effects are emptied
  with their settings kept (`synth_debug.h` counts it).
- Transfers: table CRC and 32-bit SDRAM writes in the Ethernet interrupt. Still to do in CubeMX: 8 or more receive
  descriptors (`ETH_RX_DESC_CNT`); measure the interrupt's time with the board.
- A preset's engine start runs in the main loop (one silent block) before the interrupt takes the synth back.
- Not tried on the board yet (it was unplugged): watchdog timing, fault silence, heartbeat with a real host.
- No watchdog on the M4: if it hangs, the M7 stops the network's notes (no more datagrams) and keeps playing.

## Before writing the hub (lot 3: protocol v2)

- Timestamps and a clock sync (play at a fixed latency instead of 0–2.7 ms of buffer jitter).
- Sequence numbers per sender; an owner hub id or a shared key for `PRESET`, `SELECT` and transfers.
- A portable `board_net` layer (dispatch + callbacks) with per-board glue: today `net.c` assumes the H745's two
  cores, SRAM4 addresses, MII and two 7.5 MB banks; the F746 has one core, RMII and 8 MB.

## Tooling (lot 4)

- The repository has no remote, so CI never runs; when pushed, CI should also build Debug, ARM, wasm and the board.
- `tools/check_all.sh` skips unconfigured targets silently: print SKIPPED, add a strict mode for CI.
- Warnings are caught by grepping a build's output (an incremental build hides them): `-Werror` per target.
- UBSan does not fail (`-fno-sanitize-recover=all` missing); the asan preset builds and runs only `synth_tests`.
- Golden fingerprints are all-or-nothing: add a tolerant fingerprint (levels, octave bands) that reports the size
  of a difference; compare the wasm renders with `golden.json`; apply the strict float flags to `synth_host_core`.
- No direct tests or fuzzing of the readers of untrusted input (JSON, WAV, kits, link packets, MIDI bytes).
- Generated files committed without a check that they are current (`git diff --exit-code` after the CI build).
- No version, no tags, Python requirements not pinned; the board build depends on the local STM32Cube package.
- `check_rules.py` has no self-test and skips `target/h745/app`, `plugin/` and `web/wasm/`.

## Architecture (lot 5)

- `modal` rebuilds all coefficients of every voice every block while any parameter or the pitch bend moves
  (one version counter); separate dirty flags, bend through `retune_coeffs`. A likely part of the heavy presets.
- MPE: two fingers on the same note on two channels share one voice (voices keyed by note only).
- More than 64 live parameters (`PM_LIVE_MAX`): the extra ones jump instead of gliding (preset changes on the
  sampler or drums while sounding).
- Delay synced to the MIDI clock: tick jitter retargets the delay time, a pitch drift on the echoes.
- `synth_part_kit` acts at once instead of through the event queue, and cuts sounding pads (a click).
- Sampler worst case: up to 27 taps per side at speed 4, with 12 voices and their tails.
- Extract the FM algorithm runner from `fm6.c` before writing `fm4`; per-target engine sets for the F746.
- Plugin: a state loaded while playing re-initializes the synth on the audio thread; no threaded test.
- Web: kits copied and patches parsed on the audio thread (worklet); pending requests never reject if the
  processor dies.
- wasm has no flush-to-zero: decaying tails may hit denormal slow paths in x86 browsers (to measure).
